# BlackRoad Canon

Version: 2026-09-13. Authority: Alexa Louise Amundson's current product and brand direction.

## The shared statement

We access it all at RoadOS.
We collaborate with Roadies.
We code in Road.

## One system, clear names

| Name | Meaning |
| --- | --- |
| BlackRoad | The ecosystem that brings the work together. |
| RoadOS | The portable computer and control environment where people access their work and Roadies can operate visibly within authorized boundaries. |
| Roadies | The AI collaborators and agents people work with. Their identity, context, permissions, history, and receipts belong to their BlackRoad working relationship. |
| Roadie | The meta-AI that coordinates the experience across Roadies. |
| Road | The language for expressing intent, meaning, execution, and orchestration. Use the singular name for the language. |
| Routes | The namespace. A Route is the common addressing primitive across the system. |
| Ramps | Connections to external providers, services, platforms, and infrastructure. |

RoadOS is where we access the work. Roadies are who we collaborate with. Road is what we code in. Each repository contributes a capability to this shared direction.

A provider or foundation model is one part of a Roadie's implementation. It does not define the Roadie's identity or own the user's continuity. Provider use, storage, and transmission must follow explicit permissions and the actual implementation.

## Brand language

- **Headline:** The Road. Pave Tomorrow.
- **Continuity line:** Remember the Road. Pave Tomorrow.
- **Principle:** Integration is Innovation.
- **Invitation:** Pick up your Roadies. Discover the BlackRoad together.
- **Short calls to action:** Open RoadOS. Meet your Roadies. Build in Road.

Use the three-line shared statement unchanged on repository introductions and product overviews. The invitation is campaign copy and can evolve without changing the product definitions.

Write BlackRoad, RoadOS, Roadies, Roadie, and Road consistently. Do not rename repository paths, commands, package identifiers, or public interfaces merely to update the brand. Preserve historical references where they explain lineage.

## Voice and presentation

Write with clarity, warmth, and confidence. Lead with what a person can do. Use clean grayscale presentation, balanced spacing, and a clear hierarchy. Prefer one strong headline to competing slogans or decorative badges.

## Claims and evidence

This canon defines identity and direction. Each repository must separately state what is implemented, planned, disconnected, or unverified.

The shared statement does not claim that every repository is already written in Road, that every integration is connected, or that RoadOS has been verified on every device. Preserve real implementation languages, dependency attribution, licenses, compatibility notes, and technical limitations.

Keep human authority, permissions, local continuity, inspectable actions, and truthful receipts visible in the implementation. A roadmap, model response, or marketing sentence is not evidence that an action occurred.

## Maintaining consistency

The federation source is `blackboxprogramming/.github`. Update the shared canon there first and carry the same version into participating repositories. Keep repository-specific documentation below the shared introduction. Preserve older evidence and distinguish it from current naming.

This revision follows the operator's September 13, 2026 direction. Earlier “Roads” language labels and numerical fleet/catalog summaries do not override it. Counts and service availability require a current inventory; this canon makes no fixed-count or deployment claim.
